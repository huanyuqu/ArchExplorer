# Actual framework export independent reference boundary

This reference interprets the original IR8/opset17 file node by node. Floating-point storage is FLOAT/FLOAT16/BFLOAT16; the 16-bit payload of BF16 is explicitly decoded, and arrays use FP64 to carry already-rounded values, not treating uint16 integers as floating-point values. Expected values do not call the production importer, reference, lowering, or layout resolver.

`typed_onnx_expectations.py` uses the existing rational IEEE ties-to-even rounder. FP16 has 11 significand bits and a minimum normal exponent of −14; BF16 has 8 significand bits and a minimum normal exponent of −126; FP32 has 24 significand bits and a minimum normal exponent of −126. Includes halfway-to-even, positive/negative values, subnormals, and negative zero controls. The single normal rounding relative bounds for ordinary finite numbers are 2^-11/2^-8/2^-24 respectively; subnormals use an absolute bound of half the minimum spacing instead. Overflow or non-finite comparisons are rejected independently; the general relative bound is not used for zero values.

The element-wise contract prepared this time is FP32 computation followed by explicit storage into the target dtype; matrix inner products use FP32 FMA accumulation in K order. MatMul stores once at the end; Gemm's alpha and beta scaling and bias are combined in FP32 and then stored once. Different framework fusions, reduction orders, and BLAS implementations may change the final low bits. The original framework output, official reference output, this reference, and the subsequent mapped CPU must each report errors separately; none of them can be interpreted by default as the bit-exact standard answer. This choice still needs to be bound item by item with the SIM52 frozen product exact computation contract.

LayerNormalization's axis normalization interval is from axis to the last dimension; stash_type=1 performs mean, centering, square, variance, adding epsilon, sqrt, reciprocal, and multiplying the centered value in FP32, then Normalized is explicitly cast back to the original dtype before separately Mul Scale and Add B. Mean/InvStdDev are FP32 and retain the reduction dimensions. The SIM52 formal contract allows finite non-negative epsilon and omitted B; Scale/B must exactly match the normalization suffix shape. Zero epsilon with non-zero variance and exact manual control of optional B are verified independently; the old 12 files are all positive epsilon/explicit B and are not affected by the extended domain. Only explicit stash_type=1 is prepared; other values produce diagnostics. Cross-check against the [ONNX LayerNormalization 17 specification](https://onnx.ai/onnx/operators/onnx__LayerNormalization.html#layernormalization-17) and the schema of the actually installed ONNX1.16.2; Cast boundaries are checked separately against the [ONNX Cast 13 specification](https://onnx.ai/onnx/operators/onnx__Cast.html#cast-13). The formulas in this document are based on the selected version 17 and do not depend on the current overall version of the webpage.

The supported nodes of the real CORE34 input are Constant, Cast, Identity, Gemm, MatMul, Add, Sub, Mul, Div, Erf, Sqrt, Tanh, Transpose, Softmax, LayerNormalization. Among them, Sub/Identity/Sqrt/Tanh are independent auxiliary domains and do not claim that the CORE34 original necessarily contains them; unimplemented nodes are rejected directly. The two LayerNorms and Softmax of the CORE34 decoder are explicitly FP32 in the file, with Cast back to low precision; the entire block is not labeled as metadata only.

GELU is checked against the real Div/Erf/Add/Mul/Mul decomposition, with each intermediate node having storage rounding. Torch GELU is listed separately as a fused framework operator. Errors must be reported per node with maximum absolute/relative error, zero-reference count, shape, and dtype; a whole-model uniform tolerance cannot prove the above rounding bounds. Independent preparation results do not prove product address/traffic, component services, or hardware latency; these require actual consumption by the unique candidate.

Preparation execution uses the CPU path of local Torch2.7.1+cu128, NumPy1.26.4, ONNX1.16.2, protobuf4.25.8, and does not call CUDA. The original real export environment Torch2.5.1+cpu/NumPy2.2.6 is still preserved under its original identity; different versions are not relabeled as the same execution. The BF16 official ReferenceEvaluator has been actually probed, and its errors/non-finite/huge errors are recorded per node as evidence and cannot be treated as official passing. The stash dtype mismatch of FP16 auxiliary outputs is also listed separately; a reference process return of 0 does not mean numeric qualification.
