# π0.5 非 GPU 完整图与执行边界

`WorkloadSpec(kind="pi05")` 和 `model_specs` 保留完整单设备推理的声明语义：三路视觉、prefix KV、
动作专家及 flow 循环，以及形状、mask、缓存和精度契约。
`examples/workloads/pi05-*.json` 仅保存负载描述，需要明确的架构与 mapping 才能执行。

`backend="events"` 配合 `gsm_tiled` 支持单设备的完整 `openpi.pi05.v1` 图。
架构须为明确的非 GPU 组件，例如 BF16 systolic array、支持 FP32 矩阵及向量运算的
FP32 vector unit、SRAM、DRAM 与连通网络。`applicable` 根据各算子实际 kernel 的精度和组件能力判断，
不将 BF16 当作 FP16，也不因为架构名或工作负载名而恢复 GPU 公式。

默认 `dtype="bfloat16"` 保留 FP32 初始化权重、按需产生的一份 BF16 转换副本和独立的算子精度。
SigLIP 的 QK/softmax 仍使用激活精度及 FP32 归约，Gemma QK/RMS/RoPE 和动作/时间路径仍按原图使用 FP32。
`dtype="float32"` 使用对应 FP32 分支。缺少所需矩阵精度或向量能力时明确拒绝。
完整图映射保留 prefix KV、FP32 scratch、权重存活、独立请求、输出事件及强制容量检查。

若矩阵单元不能执行结果转换，映射将 FP32 累积结果写入显式 DRAM scratch，再由 vector 单元
读回并转换为 BF16/FP16。中间结果的存活期、SRAM 工作集、DRAM/网络流量和转换指令均计入账本；
`explicit_output_casts`、`fp32_matrix_scratch_bytes` 及转换读写字节与可融合路径的
`fused_output_casts` 分别报告。该过程复用通用完整图与组件模型，不引入 π0.5 专用计时器。
通用非 GPU 多设备 ViT/CLIP 映射复用相同输出计划，以每个 rank 的局部 shape 分配临时结果。
K-shard 的 partial 直接写 FP32、allreduce 保持 FP32，仅在规约完成后按输出类型转换一次；
这条路径不叠加旧的 `partial_store` 字节补差。π0.5 的这次保留工作仍限单设备 events。

events 时延来自架构逐项声明的合成 systolic/vector 参数。它不表示 GPU 性能、真实权重动作数值、
机器人闭环或已标定的硬件时延。负载中的 `noise_seed` 是输入语义，不承担设备参数来源。

GPU ADF（包括 Accel-Sim 组件）继续拒绝 `gsm_tiled`。原生 GPU demo 的冻结范围为小 ViT/CLIP；
π0.5 的原生 Accel-Sim 执行、多设备原生 GPU/PIM 扩展仍不受支持。
未声明相应 `openpi.pi05.v1` 合同的后端必须拒绝，不能退回单次 GEMM 或伪造动作输出。
语义图、真实权重数值推理、机器人闭环和物理时延精度分别需要证据。
