# Measurement registration directory

The registry owns the complete ordered program set, work item, cubin identity and
attempt/record budgets. `microcatalog` generates both `catalog.hpp` (host data)
and `capture_catalog.hpp` (runtime directory) from that same registry. A new
registration does not require another list of names in the tracer or rehearsal.

## Canonical bytes, version 1

All integers are unsigned little endian. The exact byte stream is:

| Field | Encoding |
| --- | --- |
| Magic | 16 bytes: ASCII `ARCHCATALOG0001` followed by NUL |
| Version, total byte count, function count, attempt limit, record capacity | Five u32; version 1, attempt limit equals function count |
| Registry, cubin and shared policy source SHA256 | Three 64 byte lower case hexadecimal strings, without NUL |
| Work item | u16 byte length, then printable ASCII |
| Functions | Exactly `count` entries: u16 byte length then full ASCII C identifier, in registry order |
| Integrity digest | 32 binary SHA256 bytes over every preceding byte |

There are no optional, padding or trailing fields. Work item length is 1..128,
function length 1..255, count 1..4096, record capacity 1..4096, and total length
at most 2 MiB. Duplicate names and unknown versions are refused. The generator
uses the validated registry's budgets; these format bounds grant no resource
authority. A changed directory with a recomputed integrity digest still differs
from the registry's expected complete canonical bytes.

`arch_explorer/simulator/accelsim/catalog_policy.hpp` owns parsing, exact
compatibility, membership and attempt state. The production tracer and the pure
CPU `catalog_harness.cpp` compile this same header. `begin` requires an idle gate,
an exact previously unattempted name and remaining budget; `launch` consumes the
single armed launch; `finish` requires that launch and returns to idle. Attempts
remain consumed. Tracer file creation also retains its existing exclusive file
and output-directory checks. No prefix matching is used.

## Actual binary and build binding

Both host ELFs and the tracer contain one allocated read-only PROGBITS section
`.ae_catalog`. In the tracer this is the runtime directory itself, rather than a
sidecar description of a separate whitelist. Supplementary C export
`const unsigned char *ae_capture_catalog_v1(size_t *size)` returns those same
bytes (null size pointer returns null). Capture host requires that export and
uses the shared policy to compare it with the generated host directory before
creating the CUDA session. The existing three `sim30_capture_*` symbols and
`SIM30NV1` record transport remain version 1; their names do not define the
registered program set.

`arch-explorer.measurement-catalog-binding.v1` binds the registry, generated
files, exact three ELFs, their offline build receipts and the CPU harness. Each
build receipt preserves all project translation units, headers, generated
inputs, tool references and successful command logs. Readiness compares compiled
project sources with the frozen installation archive and generated bytes with
the registry. ELF inspection reads bytes without loading the production library.
Missing/duplicate/writable sections, legacy directories, different identities,
changed order/count/names and incomplete build inputs are refused. The CPU
harness has no CUDA dependency; its read-only `.ae_policy` and `.ae_harness`
sections bind the exact shared sources.

From an installed environment, CPU entry points are:

```bash
python -m arch_explorer.components.accelsim.microcatalog generate \
  --registry REGISTRY.json --output NEW_CATALOG
python -m arch_explorer.components.accelsim.microcatalog build-policy \
  --cxx /usr/bin/g++ --output NEW_CPU_POLICY
python -m arch_explorer.components.accelsim.microcatalog ready \
  --registry REGISTRY.json --binding BINDING.json --source SOURCE.json \
  --output NEW_READINESS.json
```

`ready` verifies the frozen installed interpreter/modules/resources, actual ELF
metadata and build/archive binding, then runs only the verified CPU policy.
It does not dlopen NVBit, query CUDA, run a measurement host or native simulator,
take a common lock, issue a lease or request a GPU window. Offline host and
tracer builders take the explicit generated `CATALOG.json` reference; each
output directory must be new.

## New runs and historical reads

Modern registrations require `measurement-design.v3` with a mandatory `catalog`
binding. New design creation and the production installation gate verify the
actual registration before a handoff, lock or host can be consumed. CPU fixture
creation uses that same gate, and its structure phase runs all entries through
the actual shared C++ policy. Synthetic records and fake boundary files carry
no hardware resource authority and cannot open a production campaign.

Historical v1/v2 designs remain readable in their original source era. Their
replay does not acquire a new directory or retroactively succeed; those designs
cannot start a new hardware window. In particular the original SIM31 failure
remains failed with 12 structure and 36 timing slots not started and null error
metrics. CPU/ELF compatibility proves no NVBit runtime callback, real capture,
timing measurement or physical accuracy. Those boundaries remain unvalidated.
